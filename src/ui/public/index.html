Làm task mới — xây một tính năng chưa có. Đầu vào là một file spec (.md, tự viết hoặc để AI sinh từ yêu cầu ở bước 2) và thư mục dự án đích; hệ thống tự thiết kế → duyệt thiết kế → chia việc → viết code (và chạy script tạo bảng vào DB nếu có chuỗi kết nối) → kiểm thử E2E bằng trình duyệt thật. Muốn bê nguyên một tính năng đã có ở dự án khác sang? Dùng tab Clone từ dự án khác →
1

Chọn thư mục dự án đích

Nơi AI sẽ ghi code: BE (server), FE (giao diện) và SQL (script tạo bảng). BE/FE là thư mục có file build riêng (pom.xml, package.json…).

Chỉ có BE hoặc chỉ có FE thì để trống ô còn lại. Nếu BE và FE nằm chung một thư mục gốc, chọn cùng thư mục đó cho cả hai ô. Để trống ô SQL thì script DB nằm trong thư mục BE. ⚠️ AI sửa trực tiếp vào các thư mục này, không tạo nhánh riêng và không sao lưu.

Cho AI đọc thêm một dự án khác để học cách team viết code (cấu trúc module, cách gọi API, component dùng chung…), cả lúc sinh spec lẫn lúc viết code. Bị chặn ghi vào đó — mọi file sinh ra đều nằm trong dự án đích. Nếu mục tiêu là bê nguyên một tính năng đã có thì dùng tab Clone.

2

Sinh file spec từ yêu cầu bỏ qua nếu đã có spec

Mô tả bằng lời thường anh muốn làm gì. AI chỉ đọc các thư mục ở bước 1 để spec gọi đúng tên module, màn hình, bảng có thật — không sửa file nào — rồi lưu spec vào thư mục anh chọn và điền sẵn vào bước 3.

3

Chọn file spec (.md)

Spec vừa sinh ở bước 2 được điền sẵn ở đây. Đọc và sửa trước khi chạy — nhất là mục Câu hỏi mở và các chỗ ghi (giả định): tiêu chí nghiệm thu trong spec là thứ bước E2E dùng để chấm đạt hay không.

4

Cơ sở dữ liệu không bắt buộc

Chỉ chọn khi tính năng có đụng tới database. Bỏ qua nếu không cần.

Hệ thống tự nhận loại DB từ chuỗi kết nối (PostgreSQL, SQL Server, MySQL), bảo AI viết script đúng cú pháp loại đó vào thư mục SQL ở bước 1, rồi tự chạy các file .sql mới vào DB ngay sau mỗi task code — mỗi file một transaction, theo thứ tự tên file. Kết nối được kiểm tra ngay lúc bắt đầu, sai thì dừng trước khi tốn token.

An toàn: file có DROP / TRUNCATE / DELETE bị từ chối, không chạy. File tên chứa rollback không bao giờ được chạy. Script đã có sẵn trong thư mục trước lần chạy không bị chạy lại. Script đã chạy mà bị sửa thì dừng và báo.

🔒 Chuỗi kết nối chỉ nằm trong bộ nhớ của lần chạy hiện tại: không lưu vào preset, không lưu vào trình duyệt, không gửi cho AI, và bị che nếu lỡ xuất hiện trong output.

5

Kiểm tra rồi chạy

Một lần chạy có thể mất từ vài phút tới vài chục phút. Có thể đóng tab — pipeline vẫn chạy, mở lại trang là thấy tiếp.

Hệ thống tự quyết mọi chuyện kỹ thuật; nó chỉ dừng hỏi khi spec bỏ ngỏ một quyết định nghiệp vụ. Câu trả lời sửa bản thiết kế đã lưu, không làm lại từ đầu.

Khi tổng chi phí ước tính chạm mức này, hệ thống dừng trước bước AI kế tiếp (bước đang chạy vẫn chạy nốt) và giữ nguyên tiến độ — chạy lại với mức cao hơn hoặc để trống sẽ đi tiếp từ đúng bước đó. Ngoài ra mỗi bước AI có trần riêng, nên một bước chạy lố không thể đốt hết hạn mức.

Dự án chưa có file .metadata-standards.yml thì chọn "Có" cũng không tác động gì — không có gì để áp dụng. Chọn "Không" không xoá hay sửa file đó, chỉ bỏ qua cho một lần chạy này.

2

Clone cái gì, từ đâu

Hệ thống tự lục repo mẫu tìm mọi thứ liên quan (SQL, BE, FE), đọc cấu trúc dự án đích, tự quyết định đặt code vào đâu, rồi port sang.

Tiếng Việt hoặc tiếng Anh, chỉ cần từ khoá — không cần đúng tên chức năng. Hệ thống tự dịch, tìm cả dạng không dấu (nghe_nghiep, NgheNghiep…) trong tên file, class, bảng, route, file dịch; nếu khớp nhiều tính năng thì chọn cái khớp nhất và liệt kê các ứng viên khác trong báo cáo.

Điền ít nhất một ô. Trỏ vào thư mục con chứa tính năng thì nhanh và chính xác hơn trỏ vào gốc repo. Repo mẫu chỉ được đọc — mọi lệnh ghi vào đó đều bị chặn.

Khi áp dụng, bước port vẫn giữ đúng code bên mẫu — chỉ báo chỗ vi phạm chuẩn, không tự cấu trúc lại. Dự án chưa có file .metadata-standards.yml thì chọn "Có" cũng không tác động gì.

Bộ thiết lập clone:
Tối ưu SQL bản demo — đọc một file SQL (procedure, function, view, câu truy vấn) của SQL Server, MySQL hoặc PostgreSQL và viết bản tối ưu để giảm tải DB, giảm thời gian chạy: điều kiện lọc dùng được index, bỏ cursor/vòng lặp từng dòng, EXISTS thay COUNT(*), bỏ SELECT * khi biết cột… Kết quả ghi ra <tên file>_optimized.sql cạnh file gốc; file gốc không bị sửa.
1

Chọn file SQL

Không giới hạn độ dài theo AI (trần kỹ thuật ~500 triệu ký tự); file lớn được tự chia theo procedure/batch, tối ưu và kiểm từng phần rồi ghép lại thành một file. AI chỉ thấy nội dung file — không kết nối DB — nên gì phụ thuộc schema thật (cột đằng sau SELECT *, index đang có) sẽ được ghi chú để anh kiểm thay vì đoán.

SQL Server .sqlplan (Save Execution Plan As… trong SSMS, nên là actual plan), PostgreSQL EXPLAIN (ANALYZE, FORMAT JSON), MySQL EXPLAIN FORMAT=JSON hoặc plan dạng text. Hệ thống tự rút ra điểm nóng (toán tử tốn nhất, quét toàn bảng, ước lượng lệch, chuyển kiểu ngầm, index thiếu) và tối ưu vào đúng chỗ đó trước; mỗi bước ghi rõ nó xử lý điểm nóng nào. Nếu ô File SQL là thư mục, ô này là thư mục plan đặt tên giống file SQL (orders.sql ↔ orders.sqlplan).

Cho AI biết cột thật, NULL hay NOT NULL, index đang có — mở khoá thay SELECT *, NOT IN → NOT EXISTS, đề xuất index không trùng.

Có chuỗi này thì hệ thống đọc schema thật và chạy thử từng bước: bản gốc, rồi thêm từng bước một — mỗi lần trong một transaction luôn rollback. Bước nào cho kết quả khác bản gốc dù chỉ một dòng thì bị loại; thời gian chạy trước/sau được đo. Rollback không trả lại số identity/sequence đã dùng hay mail đã gửi — chỉ dùng DB thử nghiệm, không dùng production. Chuỗi không được lưu lại.

Cách làm: AI đề xuất từng bước sửa (đúng đoạn code trước → sau, thuộc câu truy vấn nào); một lượt AI độc lập kiểm từng bước xem kết quả có giữ nguyên không — bước nào không được xác nhận thì bị loại; code chỉ áp các bước đã qua kiểm, lần lượt, nên phần không nằm trong bước nào giữ nguyên từng ký tự. Mọi bước (kể cả bị loại) hiện bên dưới khi chạy xong và ở đầu file kết quả.

Không giới hạn độ dài file theo AI: file dài được chia phần, chi phí tăng theo độ dài (khoảng 2 lượt AI mỗi phần ~60.000 ký tự — số phần hiện trong Tiến trình trước khi AI chạy). Chạm ngân sách thì các phần chưa tới giữ nguyên, phần đã xong vẫn được ghi ra file.

      Hướng dẫn sử dụng aidev

      1. Chọn đúng tab

      Làm task mới Xây tính năng chưa có từ một file spec. Kết thúc bằng E2E trên trình duyệt thật.
      Clone từ dự án khác Bê tính năng đã có từ repo mẫu sang. Không cần spec. Kết thúc bằng kiểm phủ, build, unit test.

      Làm task mới

      2. Các bước

      1. Đọc dự án — index file (code thuần, không tốn token) + quét quy ước một lần, lưu lại cho lần sau.
      2. Thiết kế — tự quyết mọi chuyện kỹ thuật. Spec bỏ ngỏ quyết định nghiệp vụ thì dừng và hỏi anh (xem mục 4).
      3. Duyệt thiết kế — AI khác review; lỗi nhỏ thì duyệt kèm yêu cầu sửa. Mỗi lần chạy 1 vòng.
      4. Chia việc — cắt thành các task nhỏ.
      5. Viết code — từng task: kiểm git xem có gì đổi, tra index tìm đúng file cần sửa, chỉ sửa trong phạm vi task. Sau mỗi task hệ thống tự chạy build check (compile/lint của dự án); lỗi thì dừng.
      6. E2E — Playwright chạy theo tiêu chí nghiệm thu; hệ thống tự chạy lại test để chấm, không tin lời AI.

      3. Viết spec

      # Tên tính năng
## Bối cảnh      — màn hình/API/module liên quan
## Yêu cầu       — hành vi quan sát được
## Ràng buộc     — quy ước của dự án
## Tiêu chí nghiệm thu
- [ ] Bấm X thì thấy Y.
      • Tiêu chí phải kiểm được bằng thao tác giao diện — thiếu thì E2E đánh trượt.
      • Chưa có spec: bước 2 → mô tả bằng lời → Sinh spec, đọc lại file rồi mới chạy.
      • Dự án tham khảo (tuỳ chọn): AI chỉ đọc để học cách làm. Muốn bê nguyên tính năng thì dùng Clone.
      • Database (tuỳ chọn): dán chuỗi kết nối + chọn thư mục SQL; script mới được chạy sau mỗi task, lệnh xoá dữ liệu bị chặn.

      4. Câu hỏi nghiệp vụ

      Trạng thái Chờ trả lời: thiết kế cần quyết định nghiệp vụ. Ghi câu trả lời vào ô Trả lời câu hỏi nghiệp vụ, chạy lại cùng spec — thiết kế được sửa theo, không làm lại.

      Clone từ dự án khác

      5. Các bước

      Truy tìm file trong repo mẫu → đọc quy ước dự án đích → lập bảng ánh xạ (file nào đi đâu) → port (DB → BE → FE) → kiểm phủ và kiểm nối FE↔BE bằng code → build → unit test (tối đa 2 vòng sửa). Build và unit test bỏ qua được. Đọc bảng ánh xạ trong báo cáo: kiểm phủ bắt được thiếu file, không bắt được đặt sai chỗ.

      Tối ưu SQL

      6. Quy trình mỗi file

      1. Đọc execution plan (tuỳ chọn) — .sqlplan, EXPLAIN (ANALYZE, FORMAT JSON), MySQL JSON hoặc text; rút ra điểm nóng.
      2. Đọc file SQL — file dài tự chia phần theo procedure/batch.
      3. Tối ưu — AI đề xuất từng bước (đoạn code trước → sau, thuộc câu truy vấn nào, xử lý điểm nóng nào). Một AI khác kiểm độc lập; code kiểm thêm không mất bảng/cột/hằng chuỗi. Bước không chắc giữ nguyên kết quả thì bị loại.
      4. Ghi file — <tên>_optimized.sql; đầu file liệt kê mọi bước, cả bước bị loại và lý do.
      • Logic nghiệp vụ giữ nguyên — chỉ đổi khi anh ghi rõ ở ô Yêu cầu đổi logic nghiệp vụ.
      • Schema / DDL (tuỳ chọn): cho AI biết cột thật, NULL, index đang có.
      • DB thử nghiệm (tuỳ chọn, SQL Server/PostgreSQL): mỗi bước được chạy thật trong transaction luôn rollback; chỉ giữ bước cho đúng y kết quả bản gốc và không chậm hơn. Cần lệnh chạy thử nếu file định nghĩa procedure. Không dùng production.
      • Ô file là thư mục thì tối ưu mọi .sql trong đó (plan đặt tên giống file SQL).
      • Không giới hạn độ dài theo AI; chi phí tăng theo độ dài — đặt Ngân sách tối đa cho file lớn.

      Chung

      7. Trước khi chạy

      • Commit/stash dự án đích — Task mới và Clone ghi thẳng vào thư mục, không sao lưu.
      • Cần ANTHROPIC_API_KEY hoặc CLAUDE_CODE_OAUTH_TOKEN trong .env (góc phải trên cho biết).
      • Ngân sách tối đa (tuỳ chọn): chạm mức thì dừng trước bước AI kế tiếp, giữ tiến độ.

      8. Trong lúc chạy

      • Sơ đồ tư duy (hoặc dải giai đoạn) tô sáng bước đang chạy, kèm % hoàn thành.
      • Đóng trình duyệt không dừng lần chạy. Dừng chỉ dừng lần chạy của tab đang mở; file đã ghi không bị hoàn tác.
      • Bị dừng/lỗi: chạy lại cùng thiết lập là tiếp từ chỗ dừng (Task mới, Clone). Muốn làm lại sạch: tick Chạy lại từ đầu.
